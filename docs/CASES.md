# Worked cases — the examples that keep the abstraction honest

Three uses made this a substrate; each stressed a different wall of it.

## 1. defi-vacances — where the practice was designed

Classic blind usability: an intent at job altitude, personas generated by an agent that
had never seen the code or the app's name, storylines with `ATTENTE:` expectations,
confronted by walkthroughs and flights. Established the firewall discipline (the
orchestrator owns spawning; a code-aware worker will quietly *simulate* personas), the
RÉSERVE held-out set, and the verdict vocabulary (`pass` / `mitigé` / `fail` /
`hors-champ`).

## 2. chores — same shape, plus the craft dimension

The run that proved green is not good: a localisation shipped with 486 tests passing,
303/303 strings covered, twelve tapes replaying bit-for-bit — and the owner called the
French "incredibly bad". Nine defects, every one invisible to every existing check *and*
to a persona walkthrough (a persona is charitable: it infers the intent through an
awkward screen and returns PASS). Produced the **rendered-surface reading** mode and the
craft-law expectations — laws the intent's properties switch on, now `craft@` in the
registry, cited rather than restated.

## 3. home — the counterparty is a machine, and the generalization is forced

The layout engine moved to the client; the widget IS the product and had to be run, not
assumed. The counterparty was an MCP-App *host* — a DOM, an iframe, a postMessage
bridge — so the persona was a **stand-in built from the vendor's own implementation**
(`rigs/mcp-app-host/`, from the SDK's `AppBridge`). It found three bugs in one night
that reasoning never would have (the rig README documents them), which is the evidence
behind this repo's standing hypothesis. Sibling lesson, same night: what is *not* ours
to test is the platform guarantee — cast nobody for those.

## 4 (exploratory). korean-gpt-coach — the case that proves it was never about usability

Transformation optimization: registry listing → user → paying user as hypothesis-based
design. The funnel is a tree; each optimization is a `hypothesis` with a kill-criterion;
pre-launch, personas walk the funnel blind; post-launch, analytics events confront it —
analytics being flight-recorder tapes *of humans*. Not yet run; recorded here as the
intended second consumer that keeps the extraction honest, as invest did for quern.
